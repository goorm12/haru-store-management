## 운영 상점
### STORE-03 판매자 상점 개설 — S02, P01

**필수:** 상점명, 픽업 주소, 연락처, 픽업 운영시간. 소개는 입력 지원.

- 로그인 → 정보 입력 → 검증 → 즉시 개설 → 소유권 연결·판매자 역할 부여 → 운영 홈.
- 사업자·연락처 인증 완료라고 표시하지 않는다. 사전 운영자 승인 단계 없음.
- 한 판매자가 여러 상점을 추가 가능. 다른 상점의 수량·상품·예약을 복사하거나 공유하지 않는다.
- 같은 요청 재시도로 상점이 중복 생성되지 않도록 처리한다.

**검수:** 운영 승인 대기 없이 개설되고, 다른 판매자는 신규 상점에 접근할 수 없다.


### STORE-04 운영 상점 전환·설정 — S01/S02

- 상점 하나이면 바로 운영 홈. 여러 개이면 마지막으로 접근 가능한 소유 상점으로 진입.
- 이전 상점 권한이 없어졌으면 운영 상점 목록으로 이동한다.
- 전환 시 목록·통계·검색 조건의 상점 범위를 갱신한다. 저장되지 않은 편집은 이탈 확인 제공.
- 상점 주소·운영시간 변경은 신규 공구 기본값에 적용한다. 기존 예약의 약속은 유지하며 LIST-03 절차로 변경한다.
- 상점 임의 삭제·폐점 버튼은 원문에 없는 기능이므로 본 명세에서 추가하지 않는다. 제한·탈퇴에 따른 접근 불가를 처리한다.


## 7. 공구 상품 기능

### LIST-01 판매자 공구 목록·상세 조회 — S04/S06

- 현재 운영 상점의 공구만 조회한다. 작성 중·예약 예정·예약 중·접수 중단·마감·공구 취소 상태별로 확인한다.
- 상품 정보·단가·총 수량·점유 수량·남은 수량·접수 일정·픽업 조건과 공개·숨김 여부를 확인한다.
- 공구 상세에서 수정, 접수 중단·재개, 전체 취소와 예약 현황으로 이동한다. 각 동작은 해당 기능의 권한·상태 조건을 따른다.
- 품절은 남은 수량 0 표시이며 별도 공구 상태를 만들지 않는다. 운영 제한·공구 취소로 기존 예약 이력을 지우지 않는다.
- 구매자 공개 목록과 예약 진입은 haru-store-buyer의 LIST-01에서 구현한다.

**검수:** 다른 판매자의 상점 ID로 목록·상세를 조회할 수 없으며, 상점 전환 후 이전 상점의 공구가 섞이지 않는다.

### LIST-02 작성·공개 — S05, P05·P07

**입력:** 공구 등록 정보 4.1·4.2 참조. 취소 제한 기본값은 꺼짐, 개인 한도는 미설정을 구현 기본안으로 사용한다.

- 작성 중 저장과 공개를 구분한다. 공개 시 예약 시작·마감, 1개 이상의 픽업일, 운영시간·당일 접수 마감을 검증한다.
- 예약 시작 < 예약 마감. 픽업일은 오늘 이상, 서로 중복 없음. 설정한 조건으로 예약 가능한 날짜가 최소 하나 있어야 한다.
- 당일 접수 마감은 해당 픽업 운영 종료보다 늦을 수 없는 기본안을 적용한다. 전체 예약 마감과 독립적으로 검사한다.
- 미래 시작 → 예약 예정, 현재 접수 기간 → 예약 중, 기간 종료 → 마감. 경계는 11장 참조.
- 하나의 공구는 하나의 상점에 소속. 공개 후 다른 상점으로 이동시키지 않는다.

**검수:** 15시 마감은 고정값이 아니며 판매자가 설정한 값으로 동작한다. 오늘 픽업이 이미 마감됐어도 미래 픽업 날짜가 가능하면 공개할 수 있다.

### LIST-03 기존 공구 수정 — S05, P11

| 변경 항목 | 처리 |
| --- | --- |
| 이미지·설명·상품명 | 수정 가능, 이력 보존. 기존 예약의 상품 식별·확인 정보 유지 |
| 단가 | 신규 예약에 적용. 기존 예약의 수량 증가·감소에도 예약 당시 단가 유지 |
| 총 수량 | 점유 수량 이상만 가능. 동시에 예약이 들어와도 원자적으로 검증 |
| 1인 한도 | 신규 예약·수량 증가에 적용. 기존 수량이 새 한도보다 많아도 자동 감소하지 않음 |
| 직접 취소 제한 | 신규 예약에 적용. 기존 예약 정책 스냅샷 변경 금지 |
| 예약 마감·당일 마감 | 미래 접수·수량 증가 조건 갱신. 기존 예약을 자동 취소하지 않음 |
| 기존 예약이 없는 픽업일 | 추가·수정·삭제 가능, 유효성 재검증 |
| 예약이 있는 날짜·장소·운영시간 | 기존 약속 자동 덮어쓰기 금지. 별도 처리·안내 후 변경 |
| 판매 단위·실제 상품 구성 | 기존 계약 의미가 달라지는 변경은 기본안에서 차단하고 새 공구 등록 안내 |

**일정·장소 변경 구현 기본안:** 영향 예약 목록·수량 표시 → 원래 약속 이행 가능 여부 확인 → 이행 가능하면 기존 예약 스냅샷 유지하고 신규 예약 조건만 변경 → 이행 불가하면 접수 중단, 구매자에게 사유 안내 및 합의된 처리 진행. 미해결 예약을 다른 날짜·장소로 일괄 이동하지 않는다.

자동 변경 동의·대체 날짜 제안 화면은 원문에서 후속 설계 대상으로 남아 있다. MVP 기본안은 기존 약속 유지 또는 사유 있는 판매자 취소를 통해 처리하며, 요구사항 정책을 임의 변경하지 않는다.

**검수:** 총 20개 중 12개 점유 시 11개로 축소 실패. 기존 단가 10,000원 예약에 신규 가격 12,000원이 소급되지 않는다.

### LIST-04 접수 중단·재개 — S06

- 접수 중단은 신규 예약·수량 증가 차단. 기존 예약·픽업·허용된 감소·취소·날짜 변경 유지.
- 재개 시 기간·공구 취소 여부·숨김·상점 제한을 검증한다. 운영자 제한을 판매자가 해제할 수 없다.
- 마감·품절이어도 기한이 남고 수정이 허용되면 접수 조건을 고칠 수 있으나 자동 예약 취소 없음.

### LIST-05 공구 전체 취소 — S06

- 권한 확인 → 취소 사유 → 영향 예약 수·수량 표시 → 확인 → 공구 취소 및 유효 예약 판매자 취소 → 수량 반환·이력·알림.
- 취소·픽업 완료·미수령 예약은 그대로 유지하는 구현안을 적용한다. 이들은 유효 예약 정의에 포함되지 않는다.
- 처리 중 신규 예약·변경·픽업을 같은 상태 버전 기준으로 차단하여 일부만 취소되는 경쟁을 방지한다.
- 중복 실행 시 수량이 두 번 반환되거나 알림이 두 번 생성되지 않는다.
- 예약이 있는 공구는 삭제하지 않는다. 작성 중 삭제 기능은 별도 요청 없이 추가하지 않는다.


## 9. 판매자 예약·현장 처리

### SELL-01 운영 홈·예약 목록 — S03/S07

- 현재 상점만 조회. 날짜 기본값은 한국 시간 오늘.
- 상품별 준비 수량 = 선택 날짜의 예약 확정 수량 합계. 취소·완료·미수령은 준비 수량에서 제외한다.
- 오늘 픽업 예정 건수와 수량을 구분한다. 3박스 예약 1건은 건수 1·수량 3.
- 픽업 완료 건수·미수령·픽업일 경과를 구분하여 표시한다.
- 예약번호·이름·연락처 검색, 상품·날짜·상태 필터. 페이징 기본안 적용.
- 연락처는 예약 운영 목적으로만 표시하고 공개 상품 페이지에는 구매자 정보 노출 금지.

### SELL-02 개별 예약 취소 — S08, P10

- 본인 상점·예약 확정 대상 확인 → 사유 입력 → 확인 → 판매자 취소·수량 반환·이력·구매자 알림.
- 구매자 취소 제한·전날 마감은 판매자의 공급 불가 취소를 막지 않는다.
- 이미 취소·픽업 완료·미수령이면 거절. 오기록은 SELL-06으로 정정 후 별도 판단.
- 공구 전체를 취소하지 않고 해당 예약만 처리한다.

### SELL-03 현장 결제 기록 — S08

- 실제 결제 확인 후 미결제→현장 결제 완료 기록. PG 결제 실행 없음.
- 예약 확정인 대상에 기록하는 구현 기본안. 취소·미수령 대상 결제 완료 버튼은 비활성.
- 처리자·시각 저장. 중복 완료 요청은 추가 기록·금액 계산 없음.
- 결제 기록과 픽업 상태는 독립. 결제만 완료해도 예약은 예약 확정이다.

### SELL-04 픽업 완료 — S08

- 예약번호 또는 이름·연락처로 확인 → 현재 상품·수량·날짜·금액 표시 → 실제 전달 확인 → 픽업 완료.
- 기본안은 현장 결제 완료 확인 후 픽업 완료를 허용한다. 두 개의 상태 기록을 구분하고 현장 처리 화면에서 연속 수행한다.
- 예약 확정만 완료 가능. 취소·미수령은 차단한다.
- 다른 날짜·지연 픽업은 실제 상황 확인이 필요하므로 날짜 불일치 안내를 표시하며 자동 날짜 변경을 하지 않는다.
- 픽업 완료 수량은 총 점유에서 반환하지 않는다. 동일 구매자의 같은 공구 재구매를 차단한다.

### SELL-05 미수령 처리 — S08, P12

- 예약 확정이며 픽업 운영시간 종료 후 미수령 처리하는 기본안.
- 확인 후 미수령·처리자·시각 기록. 결제 상태 임의 변경 없음.
- 자동 예약 취소·수량 반환·보관 기한 종료·폐기는 수행하지 않는다.
- 늦은 수령은 원문에 확정된 별도 자동 정책이 없다. 이미 미수령 상태이면 일반 픽업 완료를 바로 수행하지 않고 운영 확인 절차를 거친다.

### SELL-06 픽업·결제 오기록 정정 — S08, P13

- 실제 오기록 확인 → 정정할 필드 선택 → 현재·수정 후 값·필수 사유 표시 → 확인 → 이력 포함 갱신.
- 기본 정정: 픽업 완료→예약 확정, 현장 결제 완료→미결제. 사유·처리자·전후 값·시각 필수.
- 예약 상태와 결제 상태 각각 정정. 취소 예약을 정정 버튼으로 복구하거나 수량을 바꾸지 않는다.
- 픽업 상태 되돌림은 실제 수령을 취소하는 기능이 아니며 신규 예약·수량 반환을 만들지 않는다.
- 과거 날짜로 되돌리면 픽업일 경과 표시. 과거 알림을 소급 발송하지 않는다.
- 실제 돈의 환불·재결제 없음. 다른 기기의 상태 버전과 충돌하면 최신 상태 확인 후 다시 처리.

### NOTICE-S01 공지 등록·관리

운영 상점 선택 → 제목·내용 입력 → 공개 확인 → 게시. 공구 등록과 독립된 기능이며 상품 없이도 공지를 작성한다. 게시 성공 시 해당 상점을 저장한 구매자 전체에게 알림 이벤트를 생성한다. 수정·삭제는 본인이 작성한 공지만 가능하다. 구매자 댓글을 대신 수정·삭제하는 기능은 확정 범위에 없다. 판매자는 본인 답글을 작성·수정·삭제한다.

### INQUIRY-S01 문의 확인·답변

상점별 비공개 문의 조회 → 상세 확인 → 답변 작성 → 저장 → 문의 작성자 알림. 새 문의·구매자 추가 메시지는 해당 상점 판매자에게 안내한다. 다른 상점 판매자·다른 구매자에게 본문을 노출하지 않는다. 본인 답변은 수정·삭제 가능하다. 답변만으로 예약을 변경·취소하지 않는다. 필요하면 별도 예약 상세의 판매자 취소를 실행한다.

### SELL-02 보완 — 당일 취소

판매자는 픽업 당일에도 유효 예약의 사유를 입력하고 확인하면 즉시 취소한다. 플랫폼 관리자 승인·요청 대기 단계는 없다. 구매자의 직접 취소 제한과 독립적이며 취소·픽업 완료·미수령 예약은 대상에서 제외한다. 수량 반환·구매자 알림·이력 기록을 함께 처리한다.

## 프로젝트 적용 범위

이 문서는 `haru-store-management`의 판매자 반응형 웹 구현 기준이다. 회원·인증·예약 정책과 서버 검증은 [공통 기능 규칙](../common/functional-rules.md)을 따른다. 같은 계정이 두 역할을 가질 수 있지만 화면 진입과 서버 권한 검증은 역할별로 구분한다.
